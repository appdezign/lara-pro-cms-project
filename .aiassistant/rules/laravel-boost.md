# Laravel Boost guidelines

This project uses [Laravel Boost](https://laravel.com/docs/boost). The authoritative,
auto-generated guidelines live outside this file and must be read rather than guessed at.

## Read these before planning or editing

1. **`AGENTS.md`** (project root) — the full Boost guideline set for this application's
   installed packages: Laravel 13, Filament 5, PHPUnit, Pint, PHP 8.4, Herd, Spatie Ray.
   Read it at the start of a session, before proposing or writing code.
2. **`.ai/rules/index.md`** — maps file globs to rule files recording this application's
   own settled conventions. Before you create or edit any file, find the rows whose globs
   cover the path in scope and read those rule files. Also
   `grep -rin '<keyword>' .ai/rules` to catch what a glob match alone misses.
3. **`.junie/skills/*/SKILL.md`** — on-demand skill modules. Activate the relevant one
   when you start working in its domain, not after you get stuck. Currently installed:
   `laravel-best-practices`, `testing-best-practices`, `tailwindcss-development`,
   `debugging-output-and-previewing-html-using-ray`, `infer-conventions`.

Do not write code until you have read every guideline and rule matching the paths in scope.

## Use the Boost MCP tools

The `laravel-boost` MCP server is configured for this project. Prefer its tools over
shell commands and manual file reads:

- `search-docs` — query version-accurate docs for the installed packages. Use it before
  any change that depends on Laravel/Filament APIs, behavior, config, or version-specific
  syntax. Use multiple broad topic queries; omit package names from the query text.
- `database-schema` — inspect table structure before writing migrations or models.
- `database-query` — read-only queries, instead of raw SQL through Tinker.
- `application-info` — installed package versions and Eloquent models.
- `last-error` / `read-log-entries` — read application errors from the logs.
- `browser-logs` — read browser errors and exceptions (recent entries only).
- `get-absolute-url` — resolve the correct scheme, host, and port before sharing any URL.
- `record-rule` — record a durable convention into `.ai/rules` so it is shared with the
  team. Always use this rather than personal/session memory, which nobody else inherits.

## Non-negotiables

- Match the conventions of sibling files. Check for an existing component before writing
  a new one.
- Confirm a package's installed major version (`composer show --direct`, `package.json`)
  before relying on its API. Never assume a version.
- This is a Herd project: use `php artisan ...` directly; PHP is 8.4.
- Single-quote Tinker snippets to prevent shell expansion:
  `php artisan tinker --execute 'User::where("active", true)->count();'`
